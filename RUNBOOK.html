When to use this runbook

Use this runbook when you have a Shape-style capture and need named signal fields, or when a decode artifact that used to work no longer matches the request in front of you. It covers the CLI path first because that path produces the artifact every SDK consumes.

It is also the right page when you need to prove a release is usable: a complete trace, a compiled artifact, a successful decode, and a passing contract check. The procedure is written for an operator at a terminal, not for someone reading the engine internals.

Use it when

You have a launcher and kernel from one build, headers from the same browser request, and you need decoded fields, an edit round trip, or a reusable artifact for an application.

Do not use this runbook as a guide to executing captured JavaScript. Shape parses source and runs admitted symbolic recipes. It never runs the captured program. If you need browser automation or a live traffic capture, that work happens outside Shape.

Stop and ask for help before you continue if any of these are true:

  • The artifact, headers, session, or site ID came from different captures.
  • A trace exited with status 3 and you have not inspected the stopped functions.
  • You are about to overwrite the only copy of an artifact or capture.
  • You are running a release link while another Cargo build is using the same target directory.

Fast path

This is the shortest path from a clean checkout to a decoded capture. Each step has a verification point. If a step fails, jump to Troubleshooting instead of pushing forward with a partial result.

01

Build the release CLI

Run from the repository root. Release mode matters: debug builds are far slower on real captures. On a fresh machine, complete the bootstrap in Environment and inputs first.

shell
cargo build --release --locked --bin shape
export PATH="$PWD/target/release:$PATH"
mkdir -p reports
shape --help

Verify: shape --help prints the command list. Repeat the export in each new shell.

02

Prove the binary with the committed fixture

This needs no capture and no network. It confirms that the CLI, artifact loader, and header decoder agree.

shell
shape decode \
  --artifact sdk/c/tests/fixtures/artifact.json \
  --headers sdk/c/tests/fixtures/capture.json

Expect siteId: example, DeviceMemory.deviceMemory: 32, ConstantEmptyString.constant: "", and the two StorageAccessApiPresence booleans. If this fails, stop before tracing anything.

03

Trace the matching kernel

Use the kernel and launcher from the same capture. The trace writes a linked JavaScript program and a JSON report.

shell
shape trace program seeds/TOKEN.raw.js \
  --thread-cleanup --json \
  --out reports/program.js \
  --report-dir reports/cache \
  > reports/trace.json

Verify: status is complete, result.functions.stopped is empty, and result.javascript.incomplete is false. A status 3 trace still writes a program, but stopped functions become throwing stubs.

04

Pin the launcher session

The launcher is also the initializer. Pin the traced program and extract the session member for the next command.

shell
shape pin --input reports/program.js \
  --init seeds/TOKEN.async.js --out reports/seed.json

python3 -c 'import json; json.dump(json.load(open("reports/seed.json"))["session"], open("reports/session.json", "w"))'

Verify: reports/session.json contains transactionToken, alphabet, shuffleKey, eight keys, and an optional nonce.

05

Compile and save the decode artifact

This is the expensive step. It compiles the signal recipes once so later requests can skip source analysis.

shell
shape decode --seed reports/program.js --input-kind program \
  --headers headers.json --session reports/session.json \
  --float-byte-order little \
  --save-artifact reports/artifact.json \
  --out reports/decoded.json

Verify: reports/decoded.json contains positionalSignals, and reports/artifact.json exists. Saving an artifact always verifies signal and header re-encoding.

06

Reuse the artifact for the next request

Keep the same site, build, and session pairing. The artifact replaces the seed, session, and source files for decode.

shell
shape decode --artifact reports/artifact.json \
  --headers next-headers.json \
  --out reports/decoded-next.json

Verify: the output carries the expected named fields and the same siteId. If the site ID differs, recompile from that site's capture.

Network boundary

Build-time fetches for Cargo and npm are separate. After the first build, shape seeds fetch is the only command that uses the network. Static analysis never executes captured JavaScript or WebAssembly. If you need the capture bytes, save them before analysis and keep the exact files.

Build the CLI

The CLI is a single binary named shape. Build it from the repository root with the lockfile so the dependency set is the one this checkout was tested with. Rust 1.92+ plus CMake and a C/C++ toolchain are required: the HTTP stack builds aws-lc-sys, so a bare Rust install is not enough.

shell
cargo build --release --locked --bin shape
export PATH="$PWD/target/release:$PATH"
mkdir -p reports
shape --help

The first build resolves and downloads crates. Later builds reuse Cargo's cache. The binary lands at target/release/shape. The reports/ directory is Git-ignored and is the expected home for local outputs.

Build checks

  • shape --help lists the command families.
  • shape <command> --help shows the flags for that command. Do not assume a flag is shared across commands.
  • shape decode against the committed fixture returns the expected three signals.
  • No existing output is overwritten unless the command supports and receives --force.
Release build

Use release mode for raw-seed recovery. Debug builds are much slower and can make a normal capture look like a hang.

If the command is not found

The repository binary is not on PATH. Re-run the export line from the repository root in the current shell, or call ./target/release/shape directly. A stale installed binary is a different problem: source edits do not update an older installed build.

Build the SDK

The shared native build covers the C ABI, the Python and Node bindings, and the Go static library. It also builds the Node addon. Rust callers depend on the repository's root crate by path and do not need this step.

shell
rustup component add llvm-tools
scripts/build-sdk.sh
mkdir -p reports

The script is restartable. Rerun it after a failure or after native source changes. It overwrites its own outputs and never stages or commits anything. Do not run it at the same time as another Cargo build that uses the same target directory.

One link at a time

A machine can only take one release link at a time. Wait for the SDK build to finish before starting another release build in the same target directory.

After native changes

Rebuild the installed bindings. A stale installed library does not acquire new operations from source edits. For Node-only work, sdk/node/build.sh rebuilds the addon, but it still needs the matching libshape beside it.

Acquire a matching capture

Start with a launcher and kernel from one build. The registry exists so you do not reconstruct provider URLs by hand. Inspect the registry first, then fetch a validated entry.

shell
shape seeds sites
shape seeds fetch --site NAME --out seeds
shape seeds parse seeds/TOKEN.async.js --base-url 'https://assets.example.test/launcher.js?async'

fetch writes two sibling files named after the capture token: TOKEN.async.js and TOKEN.raw.js. A direct-kernel entry point writes only TOKEN.raw.js and needs --seed on import. parse writes nothing and makes no request; it reports the token and resolved kernel URL.

Import files you already saved

Use import when a teammate sent you the launcher and kernel, or when you saved them from the browser Network panel. The launcher supplies the capture identity.

shell
shape seeds import downloads/abc123.raw.js \
  --launcher downloads/abc123.async.js \
  --out seeds/imported

shape seeds import downloads/abc123.raw.js \
  --seed abc123 --out seeds/imported

Pass exactly one of --launcher or --seed. Supplying neither or both is a usage error. Import validates that the kernel classifies as a raw kernel before writing, and it does not authenticate that the two files belong together.

Headers and session

Shape does not produce headers. Capture them from the same browser request and reduce them to suffix keys with a site label:

json
{
  "siteId": "example-site",
  "headers": {
    "a": "ZCcDA5M-Wp6u...",
    "a0": "_kDqP0McfRa...",
    "b": "-upu45s",
    "c": "AIAS-MKh...",
    "d": "ADYAhICB...",
    "f": "A71QDMOh...",
    "z": "q"
  }
}

The real HTTP names are the capture prefix plus the suffix, commonly x-...-a, x-...-a0, and so on. The artifact supplies the prefix. siteId is a label, not an HTTP header, and it must match the artifact.

The launcher's detail.init(...) call carries the session. Pin the launcher once and extract the session member, or pass the whole launcher to shape pin --init. No separate init extraction is required.

Matching set

Keep the artifact with its matching site, build, and session. A token from one capture with keys from another is not a merge problem; it is an invalid input.

Trace the program

trace program walks every reachable VM thread and links the result into one JavaScript file. This is the step that turns a minified kernel into a program the signal finders can read.

shell
shape trace program seeds/TOKEN.raw.js \
  --thread-cleanup --json \
  --out reports/program.js \
  --report-dir reports/cache \
  > reports/trace.json

The command writes the linked program to --out and the structured report to stdout, which the shell redirects to reports/trace.json. Summaries go to stderr. The fixture trace recovers 602 functions and takes a few seconds.

Check completion before using the program

Read the report. Do not treat the existence of program.js as proof that every reachable function completed.

json
{
  "status": "complete",
  "result": {
    "functions": { "stopped": [] },
    "javascript": { "incomplete": false }
  }
}
  • status: complete is the only status that authorizes the rest of the fast path.
  • result.functions.stopped must be empty.
  • result.javascript.incomplete must be false.
  • A status 3 trace still writes a program. Stopped functions become throwing stubs that name their stop.
Partial trace

A partial trace is useful for diagnosis, not for a release artifact. Inspect result.functions.stopped, raise --steps, retry without --thread-cleanup, or use branch overrides before you compile recipes.

Trace one function instead

Use trace thread when you know the entry coordinates and want to inspect one walk. The entry pc, state, and initial slots come from shape kernel show.

shell
shape trace thread tests/fixtures/kernels/javascript/kernel.raw.js \
  --pc 0 --state 0 --initialslots 2,0,3,1 \
  --out reports/thread.js

shape trace cleanup-thread reports/thread.js --out reports/thread-clean.js

trace thread returns 0 for a complete walk, 3 for a stop, 4 for an undeclared generated name, 5 for a self-check difference, and 1 or 2 for errors. Use --partial only when you want diagnostic output from a stopped prefix; program and corpus mode never emit incomplete traces that way.

Reuse the kernel cache, not the trace

--report-dir caches compiled kernel artifacts. A cache hit skips kernel compilation on a later trace. It does not skip tracing, and it does not make a previous trace result valid for a different entry or capture. Use --steps to bound each function walk when a capture is large.

For branch decisions, pass a JSON array of real branches with --not-fake-branches, or a JSON object of forced branches with --fake-branches. A position may not appear in both files. Without either option, the walk is unchanged.

Compile the artifact

A decode artifact holds the layout, cipher settings, session defaults, and executable signal recipes. Compile it once per matching site, build, and session. After that, decode does no source analysis.

Pin the traced program and session

shell
shape pin --input reports/program.js \
  --init seeds/TOKEN.async.js --out reports/seed.json

python3 -c 'import json; json.dump(json.load(open("reports/seed.json"))["session"], open("reports/session.json", "w"))'

The pinned layout is a shape-seed-layout/1 document. Its session member is the parsed session. The session must belong to the same launcher, kernel, and headers. When you supply a replacement session, pass its complete token and cipher material; individual fields are not merged with the previous session.

Compile and decode in one pass

shell
shape decode --seed reports/program.js --input-kind program \
  --headers headers.json --session reports/session.json \
  --float-byte-order little \
  --save-artifact reports/artifact.json \
  --out reports/decoded.json

--float-byte-order records how the collecting browser wrote native floats. It is required when the seed emits them and is saved in the artifact. little and big are the only values. Guessing produces decode failures rather than wrong values.

What was saved

reports/decoded.json contains named positionalSignals plus the retained report context. reports/artifact.json contains the reusable recipes. They are different documents and neither replaces the other.

Explicit direct mode

Use --direct only when you need explicit source-format analysis without lifecycle certification. It is opt-in, defaults the seed to a traced program, and defaults the float byte order to little. It does not certify strict consumer support.

shell
shape decode --direct --seed reports/program.js \
  --session reports/session.json --headers headers.json \
  --float-byte-order little --verify \
  --save-artifact reports/direct-artifact.json \
  --out reports/decoded-direct.json

Direct provenance persists in the artifact. A later --artifact load uses the recorded mode automatically. --direct requires --seed and conflicts with --artifact and --schema-only. It cannot reinterpret a saved strict artifact.

Schema only

If you need the static schema without a session or capture, export it without decoding:

shell
shape decode --schema-only --seed reports/program.js \
  --input-kind program --schema-out reports/schema.json

The compact schema describes signals. It cannot decode and it is not a substitute for --save-artifact.

Decode, edit, encode

The CLI decodes named fields. The SDK also encodes edited fields back into headers. Keep the full decoded payload when you edit; saving only the named map deliberately constructs a new payload with fresh prefixes and layout defaults.

Decode with a saved artifact

shell
shape decode --artifact reports/artifact.json \
  --headers next-headers.json \
  --out reports/decoded-next.json

The committed sample pair produces this trimmed result. The full document also carries report channels, seeds, and metadata.

json
{
  "siteId": "example",
  "positionalSignals": {
    "ConstantEmptyString": { "constant": "" },
    "DeviceMemory": { "deviceMemory": 32 },
    "StorageAccessApiPresence": {
      "hasStorageAccess": true,
      "requestStorageAccess": false
    }
  }
}

Add --verify when you want an ordinary decode to require byte-identical re-encoding. --save-artifact always performs that verification. Successful decoding does not mean every edit can be encoded; the compiled wire recipes must support the requested value.

Edit and re-encode in an SDK

Load the artifact once, keep it outside the request loop, and pass the whole decoded object to encode. The examples change DeviceMemory.deviceMemory from 32 to 16 and write rebuilt headers.

javascript
import { readFileSync, writeFileSync } from 'node:fs';
import { Generator, stringifyJSON } from './sdk/node/index.mjs';

const generator = await Generator.loadAsync(
  readFileSync('reports/artifact.json'),
);
try {
  const decoded = await generator.decodeAsync(
    readFileSync('next-headers.json'),
  );
  const memory = decoded.positionalSignals.DeviceMemory;
  if (!memory || typeof memory.deviceMemory !== 'number') {
    throw new Error('Capture has no numeric DeviceMemory field');
  }
  memory.deviceMemory = 16;
  const encoded = await generator.encodeAsync({ decoded });
  const json = stringifyJSON(encoded);
  if (json === undefined) throw new Error('Capture could not be serialized');
  writeFileSync('reports/node-headers.json', json);
} finally {
  generator.close();
}
python
import json
from pathlib import Path
import shape

artifact = Path("reports/artifact.json")
headers = Path("next-headers.json").read_bytes()
with shape.Generator.load(artifact) as generator:
    decoded = generator.decode(headers)

go
package demo

import (
    "encoding/json"
    "fmt"
    "shape"
)

func EditCapture(artifact, headers []byte) (*shape.Capture, error) {
    generator, err := shape.Load(artifact)
    if err != nil { return nil, err }
    defer generator.Close()

    decoded, err := generator.Decode(headers, shape.DecodeOptions{})
    if err != nil { return nil, err }
    fmt.Println(decoded.PositionalSignals)
    memory, ok := decoded.PositionalSignals["DeviceMemory"]
    if !ok { return nil, fmt.Errorf("capture has no DeviceMemory signal") }
    memory["deviceMemory"] = json.Number("16")
    return generator.Encode(shape.EncodeRequest{Decoded: decoded})
}
rust
use shape::Generator;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let generator = Generator::load(&std::fs::read("reports/artifact.json")?)?;
    let capture: shape::signals::decode::CaptureHeaders =
        serde_json::from_slice(&std::fs::read("next-headers.json")?)?;
    let mut decoded = generator.decode(&capture, None, Default::default())?;
    let memory = decoded.positional_signals.get_mut("DeviceMemory")
        .ok_or("capture has no DeviceMemory signal")?;
    memory["deviceMemory"] = serde_json::json!(16);
    let headers = generator.encode(&serde_json::to_value(&decoded)?, None)?;
    println!("{} {}", headers.site_id, headers.headers.iter().count());
    Ok(())
}

C callers link libshape and exchange JSON text with explicit ownership. The C guide has the complete request and handle lifecycle. Rust callers depend on the repository's root crate by path and do not need the C ABI build.

Keep the whole payload

Encode the whole decoded object, not just positionalSignals. The retained report carries raw signal bytes, other channels, seeds, keysets, header context, and per-signal prefixes. Encoding the named map alone constructs a fresh payload.

Encoding an unchanged full payload with a matching artifact and session reproduces all six captured header values exactly. An edit retains unedited signals where the codec supports it, but shared framing and encryption can change header bytes beyond the edited field. An edit is not a promise of unchanged ciphertext elsewhere.

Unsupported edits are refused. Inspect the signal with explain, check its supported shape and literal or count constraints, and keep the full decoded object. For a new session, pass the complete replacement to decode, explain, and encode; a session override replaces the whole session.

Verification gate

Do not call the work complete because a command printed JSON. The release gate is a set of observed results. Run every check that matches the surface you changed, and record the command output in the change or incident note.

shell
# CLI fixture and full test suite
shape decode --artifact sdk/c/tests/fixtures/artifact.json \
  --headers sdk/c/tests/fixtures/capture.json
cargo test

# Documentation and signal data checks
node --test scripts/docs-links.test.mjs
node scripts/docs-links.mjs
node scripts/signal-data.test.mjs

# SDK checks after scripts/build-sdk.sh
npm --prefix sdk/node test
uv run --no-project python sdk/tests/contract.py

The five-language contract harness requires matching native code and bindings. It fails when a runtime or compiler is missing; it does not silently omit a language. Run it after scripts/build-sdk.sh, not against an older installed library.

shell
SHAPE_LIBRARY="$PWD/sdk/python/shape/lib/libshape.dylib" \
SHAPE_TEST_ARTIFACT="$PWD/sdk/c/tests/fixtures/artifact.json" \
SHAPE_TEST_HEADERS="$PWD/sdk/c/tests/fixtures/capture.json" \

Use libshape.so on Linux. The SHAPE_LIBRARY path must point at the current optimized library, not a stale build. Pure boundary and lifetime checks can run without a native library by selecting their test classes.

What counts as evidence

A complete trace, a saved artifact, and a successful decode are separate facts. Keep the command, the exit status, and the output path for each. A screenshot of a JSON blob is not enough to prove that the artifact was built from the same capture.

Test matrix

Choose the smallest check that covers the change, then run the release gate before handoff. The full suite is slow; focused targets are for local iteration.

Trace stop triage

Read the stop reason before changing flags. The same exit code can mean a budget limit, an unsupported handler, or malformed input.

  • dispatch step budget reached: raise --steps or accept a partial result.
  • state N has no proven table row: the capture's table does not cover this dispatch. It is not a supported kernel on this path.
  • selector N is unsupported: the handler exists, but no recipe admits it. This is a coverage gap, not malformed input.
  • dispatch PC ... is outside the ... image: malformed bytes, or an entry or slot declaration that does not match the image.
  • branches cannot join at pc ... state ...: the two sides met with VM state the tracer cannot merge.
  • dispatch revisited pc ... state ... without progress: a loop the walk did not recognize.
Do not retry blindly

Changing a flag without reading the stop reason can hide the problem. If the failure looks like an internal panic, record the operation, CLI or native version, options, error code, and a minimal reproduction. The SDK returns a panic error code instead of crashing your process.

Rollback

Rollback here means returning to a known matching set, not undoing unrelated work. Captures and artifacts are expensive to recreate. Preserve them.

Never destroy evidence

Do not run git reset --hard, git clean, or delete a capture to fix a decode failure. Rename the bad output, keep the previous artifact, and rebuild from the matching launcher, kernel, session, and headers.

Quarantine a bad artifact

Move the suspect artifact aside. Do not overwrite the only copy. Then recompile from the preserved inputs with a new output name.

shell
mv reports/artifact.json reports/artifact.bad.json
shape decode --seed reports/program.js --input-kind program \
  --headers headers.json --session reports/session.json \
  --float-byte-order little \
  --save-artifact reports/artifact.rebuilt.json \
  --out reports/decoded.rebuilt.json

If the rebuilt artifact decodes the same capture correctly, switch consumers to the new path. Keep the bad artifact until the incident note is closed; it is evidence of what failed.

Roll back a native build

A stale or mismatched native library can make a working source tree look broken. Re-run scripts/build-sdk.sh against the current checkout, then rerun the contract harness. If you need the previous library, restore it from your release artifact store rather than copying a random build from another machine.

Roll back a program or trace

Keep the last complete program.js and its trace.json. If a new trace is partial, do not compile recipes from it. Restore the previous complete pair, confirm the status fields, and use the matching artifact for that build. Re-trace only when you have the matching kernel and a reason to believe the stop is resolved.

Background

Shape turns captured JavaScript into inspectable VM facts and, where the source supports it, traced JavaScript. The architecture separates source preparation, static proof, bounded execution, and code emission. Each stage carries the evidence needed by the next.

pipeline
seed.raw.js -- deob ---------------> readable kernel JavaScript
            +- trace program ------> traced program (linked JavaScript)
init.js ----- session.from_initializer --> session (token, alphabet, keys)
                                           |
traced program + session + site ID -- artifact.compile --> decode artifact
                                                           |
headers.json ---------------------------- decode <----------+
                                           |
                             named fields in positionalSignals
                                           |
                             explain one signal, edit fields
                                           |
headers.json <--------------------------- encode

Static analysis, not execution

Source preparation runs CLEAN, RENAME, FIND, and EXTRACT, followed by presentation passes. It records typed facts and their evidence. The tracer runs admitted symbolic recipes. It does not execute captured JavaScript or WebAssembly. A handler in the operation table does not by itself prove that its behavior is admitted for tracing.

Two reuse points

A kernel artifact shares source analysis across process boundaries. A decode artifact carries the compiled recipes and session settings for repeated decoding. They solve different problems and cannot replace one another. A cache hit skips kernel compilation; it does not skip tracing. A saved decode artifact skips source analysis on reuse; it does not make a different capture compatible.

Why the matching set matters

Coordinates, handler keys, salts, and layouts belong to a particular build. The artifact stores session defaults and recipes for that build. Headers from another build can look valid and still fail verification. Keep the artifact with its matching site, build, and session, and re-run analysis for a different build.

Performance notes

Raw-seed recovery compiles kernel facts, traces reachable threads, cleans the recovered program, then extracts layouts and compiles recipes. That is a seconds-to-minutes operation. Use release builds and bound the work with --steps or SDK jobs. Loaded artifacts are immutable and reusable; each decode returns its own mutable request data. Copy a decoded object if you need to keep both the original and edited versions.

Security and data handling

Only shape seeds fetch uses the network. Static analysis never executes captured code. Private programs, initializer material, and generated artifacts should stay local and out of tracked fixtures. Use the Git-ignored reports/ directory for local outputs, and keep captured data out of src/.
